### QA-R7-02　`savedPathOf()` 只比对文件名，不比对目录（**本轮最需要你盯的一条**）

`src/content-md.ts:568-571`：

```ts
const savedPathOf = (handle) => {
  const pagePath = currentFilePath();
  return basename(pagePath) === handle.name ? pagePath : '';
};
```

它只比 **basename（文件名）**，**完全不看目录**。

**触发条件**：在另存为面板里**没有导航**、直接确认，而面板的默认落点是**上层目录**
（`startIn` 只能精确到 Desktop/Documents/Downloads/… 这一级，**到不了子目录**）。

**具体例子**：你打开的是 `~/Downloads/sub/deep/r7-deep.md`，`startIn` 只能把面板送到
**`~/Downloads` 根目录**（送不进 `sub/deep`）。此时你若直接点「存储」，文件会落在
`~/Downloads/r7-deep.md` —— 而**不是**你正在看的 `~/Downloads/sub/deep/r7-deep.md`。
因为两者 basename 都是 `r7-deep.md`，`savedPathOf` 会**误判成同一个文件**，
编辑器回显的路径仍是 `…/sub/deep/r7-deep.md`，但**你的修改其实写到了上层的另一个文件里**。

> 若 `~/Downloads/` 下**恰好已有**同名 `r7-deep.md`，它会被**静默覆盖**。

**请这样验证（对应 A3 / G4）**：

1. 先建两个同名文件：`~/Downloads/r7-deep.md`（内容写 `AAA`）和 `~/Downloads/sub/deep/r7-deep.md`（内容写 `BBB`）
2. 冷启动打开**深层那个** `file:///Users/bot/Downloads/sub/deep/r7-deep.md`（应显示 BBB）
3. 改成 `BBB-edited`，Cmd+S
4. 面板停在 `~/Downloads` 根 → **不要导航**，直接「存储」（会提示替换，选替换）
5. **核对**：`cat ~/Downloads/r7-deep.md` 与 `cat ~/Downloads/sub/deep/r7-deep.md`

- 若 `~/Downloads/r7-deep.md` 变成了 `BBB-edited`，而深层那个仍是 `BBB` → **限制复现**，
  且编辑器还回显深层路径（回显不可信）。请记录截图反馈。
- 规避方式：**在另存为面板里手动导航到原文件所在的那个子目录**再确认。

> 这是本轮**已知未修**项，不算 R7 验收失败项（R7 只承诺"按目录智能定位 + 预填文件名"，
> 而 FSAA 的 `startIn` 本身就到不了任意子目录）。但它有**静默写错文件**的风险，
> 请你在真机确认严重程度，再决定是否要工程师加「落盘后校验完整路径 / 目录不符时提示」。

### QA-R7-01　Open 弹窗的「Markdown」筛选漏了 `.mdown`（P2，已路由工程师）

`src/content-md.ts:441` 的 accept 是 `['.md', '.markdown', '.mkd', '.txt']`，
比权威白名单 `MD_EXTENSIONS`（`src/content-md.ts:135`）少一个 `.mdown`。
→ 点 Open 时 `.mdown` 文件在「Markdown」筛选下不可选。
**可绕过**（面板里切 All Files 即可选），故不阻塞 R7 发布。对应用例 **E4**。

> 注意：**Save 侧的 `.mdown` 已修好**（用例 B4 验的就是它）。这里出问题的只有 **Open 侧**。
