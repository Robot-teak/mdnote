# Mermaid 配色存档（三版色板）

> 用途：**把所有历史色板留档**，为将来做成「用户可选配色」的配置项做准备。
> 当前生效的是 **v3 冷色带**。v1 / v2 **已不在代码中**，只存档在此。
> 色值位置（生效版）：`src/lib/mermaid-renderer.ts` 的 `LIGHT_PALETTE.ramp` / `DARK_PALETTE.ramp`。

---

## 一、三版色板对照

| 版本 | 色相策略 | 明度策略 | 状态 | 用户反馈 |
|---|---|---|---|---|
| **v1** | 全色环，h = 0°+30°×i | **全档同明度** | 已弃用 | 「颜色太刺眼」「文字和颜色混在一起」→ 后又「颜色差异太相近，看着都好像」 |
| **v2** | 全色环，h = 0°+30°×i | **相邻档交替明度** | 已弃用（用户认可其"不刺眼/对比"，但嫌偏棕） | 「不刺眼了、对比也明显了，但色系偏棕」 |
| **v3** | **冷色带 h ∈ [195°,345°]，蓝优先排序** | 相邻档交替明度 | ✅ **当前生效** | 「可以，现在就先用这个」 |

## 二、v1（弃用 · 全色环 + 同明度）

- 配方：LCh，`L*` 亮 90 / 暗 25（**全档同一值**），`h = 0° + 30°×i`，绝对彩度 C_abs = 0.114 / 0.200
- 实测：ΔE00 最小 **4.04（亮）/ 5.79（暗）**，未达标对数 14 / 6 —— 这就是"看着都好像"的实证
- 缺陷根因：彩度被压到 0.114 后 Lab 彩度半径仅约 14，相隔 30° 的弦长 `2·C*·sin15° ≈ 7`，**纯靠色相在这条彩度上限下数学上不可能达到 ΔE≥10**（穷举最优仅 5.03）

## 三、v2（弃用 · 全色环 + 交替明度 · 用户称"偏棕"）

- 配方：LCh，`L*` ∈ {**72, 88**} 亮 / {**18, 36**} 暗 **交替**，`h = 0° + 30°×i`，C_abs = 0.114 / 0.200
- 实测：ΔE00 最小 **10.39 / 14.46**（修好了 v1 的问题）；文字对比最低 7.88 / 5.03；彩度与用户认可版持平
- 为什么"偏棕"：色相铺满整圈，**必然**横扫 36°~120° 暖区（红/橙/棕/卡其/橄榄）—— 亮色 `#bfada2`(褐灰)、`#e5dcc8`(米黄)、`#acb497`(橄榄)，暗色 `#704c3d`、`#3a2907`、`#535825`
- 外部依据：ColorBrewer `Paired`（12 色 = 6 色相族 × 明暗两档）就是同一结构

## 四、v3（当前生效 · 冷色带淡蓝）

- 配方：LCh，色相带 **CIELAB h ∈ [195°, 345°]**；**按"离标准蓝 270° 越近越靠前"重排**（cScale0 = 最正的蓝 278°）；`L*` 仍交替；彩度改用**感知彩度** `C* = hypot(a*, b*)`，亮 ≤16.7 / 暗 ≤36.6
- 实测：色相 12/12 在带内；ΔE00 最小 **10.23 / 10.28**；对比度最低 5.02 / 4.70；C* max 16.7 / 21.4

### ⚠️ 这一版换掉了"不刺眼"的度量尺子（重要）

从**物理彩度** `C_abs = (max−min)/255` 换成**感知彩度** `C* = hypot(a*, b*)`。
原因：C_abs 是**色相盲**的 —— 同为 C_abs = 0.114，`#f1d4ed`(紫) 的 C\* = **16.7**，而 `#d3ddf0`(蓝) 只有 **10.4**。
即：用户真机认可的其实是「**C\* ≤ 16.7**」，而非「C_abs ≤ 0.114」。
反证：若坚持旧尺子，蓝区只能拿到 C\*≈10，12 档塞不进 ΔE≥10（穷举最大 minΔE 仅 8.43 / 8.85）。

## 五、将来做成「用户可选配色」时必须注意的事

1. **缓存已经自动处理**：`MERMAID_PALETTE_VERSION` 是对两套色板 JSON 做 FNV-1a 的**指纹**，改任何色值 → 指纹变 → 缓存 key 自动变 → 旧缓存自动 miss。**不要手写版本号常量**（漏 bump 一次就白改）。
2. **探针断言是按"单一色板"写的，配置化后必须参数化**：`qa-mermaid-11-run.mjs` 里的色相带 `HUE_BAND = 195`、彩度上限、ΔE 门限，都是针对当前这一套写死的。多套色板共存时，要么每套各一组期望值，要么只断言"通用约束"（对比度/ΔE）而把色相带作为**该套色板的声明式元数据**随色板一起提供。
3. **12 档覆盖不能丢**：`cScale8..11`、`pie9..12` 必须来自同一条斜坡，否则会退回 mermaid 自己的派生色，脱离全部约束（这也是当初否决"12 档减到 8 档"的理由）。
4. **journey 不要再有第二份色清单**：`actor0..5` 现在由斜坡前 6 个派生。曾经存在独立字段 `actorIcons`，已删除 —— 将来改一处不改另一处会让"可区分"约束静默失效。
5. **明暗两套必须同色相**：第 i 档在亮/暗下色相相同（只改 L\*/C\*），否则切换主题时同一个系列会换颜色。
6. **前几档决定整图观感**：mermaid 里 2~4 色的图（饼图/泳道/时间轴/旅程）只用斜坡前几档。排色顺序本身就是设计变量（v3 因此让第 0 档是最正的蓝）。
7. **`securityLevel: 'strict'` 不许降级**，`theme` 保持 `default`/`dark`（改成 `base` 会连带改变 mermaid 的 `darkMode` 派生行为）。
